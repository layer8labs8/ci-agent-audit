Can a stranger hijack the AI agent in your CI?

Many teams let an AI agent triage issues or review pull requests. If outside text reaches its prompt, anyone with a GitHub account can try to give it orders. Paste a workflow and check yours.

pip install ci-agent-audit

How the attack works


    

  1. A stranger opens an issue
    Anyone with a GitHub account can do it, and the text can say anything.
    2. 

  2. Your workflow pastes it into the prompt
    The agent gets your instructions and theirs as one block of text. It can't reliably tell them apart.
    3. 

  3. The agent may obey, with your access
    Your token, tools, and secrets are now in reach of someone you've never met.
    4. 




This attack is called prompt injection. The CI version is often called PromptPwnd.







What it checks


Protection you already have lowers the severity. Prompt injection drops from Critical to High with a read-only token, and to Medium behind a complete author check.

Pre-commit


repos:
  - repo: https://github.com/layer8labs8/ci-agent-audit
    rev: v
    hooks:
      - id: ci-agent-audit







GitHub Action


name: AI workflow security audit
on: [push, pull_request]

permissions:
  contents: read

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: layer8labs8/ci-agent-audit@v
        with:
          paths: .github/workflows
          fail-on: high







Use it next to a general linter such as zizmor or actionlint, not instead of one.







What it can't do


    

  • A scanner finds risky patterns, not proven attacks. A clean report doesn't mean a workflow is safe.
    • 

  • It reads one file at a time, so it can't follow reusable workflows or composite actions.
    • 

  • It can't see an agent reading issues through its own built-in tools when the workflow doesn't mention them.
